🧩 Hyperframes: overview

Hyperframes makes video from web pages. You write HTML, CSS and JavaScript, a command renders it to MP4. It is open source (Apache 2.0), made by HeyGen, and designed for AI agents to write.

Based on the official docs at hyperframes.heygen.com and on running version 0.9.67 in this project. Where a number is mine, it says so.

How it works

A video is an HTML file. Three things make it render:

  • Timed elements. The root element has data-composition-id, data-start, data-duration, data-width and data-height. Each visible piece is class="clip" with its own data-start, data-duration and data-track-index.
  • A paused animation timeline. Motion is a GSAP timeline, created paused and registered as window.__timelines["your-id"].
  • Seeking, not playing. The renderer jumps the timeline to the exact moment of each frame, captures it in headless Chrome, and encodes the frames with FFmpeg. Because it seeks instead of watching a clock, the same frame comes out the same every time.

The rule that matters most: only deterministic logic. No Date.now(), no Math.random(), no network fetches during render.

<div data-composition-id="main" data-start="0" data-duration="10"
     data-width="1920" data-height="1080">
  <h1 id="title" class="clip" data-start="0" data-duration="10"
      data-track-index="0">The end of the company</h1>
</div>
<script>
  const tl = gsap.timeline({ paused: true });
  tl.fromTo("#title", { opacity: 0 }, { opacity: 1, duration: 0.5 }, 0);
  window.__timelines["main"] = tl;
</script>

The work loop

  1. Write or edit the composition (an agent does this from your instructions).
  2. npm run check: lint, runtime, layout, motion and contrast in one go.
  3. npx hyperframes snapshot --at 1,3,5: PNG frames to look at before rendering.
  4. npm run render: the MP4.

Where this project is

The video/ folder is still the blank starter. After you approve the storyboard, I build the ten scenes there as sub-compositions with placeholders, then swap in your real footage.
