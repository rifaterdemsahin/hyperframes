🛠️ Rendering paths

Every path starts with the same project. The difference is who runs Chrome and FFmpeg, and where.

From the official Choose a rendering path and Render from the command line docs, checked 18 Nov 2026.

The paths

PathUse it whenYou operate
CLI (local or CI)Rendering while you create, or in a CI job. Start here.The machine running the command
ProducerA Node app starts renders and needs progress and cancelThe Node service
EngineBuilding specialised frame-capture infrastructureCapture, encoding, orchestration
HyperFrames CloudRender without local Chrome or FFmpegNothing beyond the request
AWS LambdaDistributed renders in your own AWS accountThe deployed AWS stack
Google Cloud RunDistributed renders in your own Google Cloud accountThe deployed GCP resources
Hosted templatesA small preview app plus render API on Vercel, Cloudflare or ModalThe hosting account

The docs' rule: pick the highest-level surface that completes the job (CLI, then Producer, then Engine). For this video that is the CLI on your own computer. See Cloud vs local speed for why.

Local render

npx hyperframes check
npx hyperframes render --output final.mp4

Rendering uses parallel workers by default (--workers auto); each worker is a separate Chrome process.

Cloud render

npx hyperframes cloud render ./project --output video.mp4   # HeyGen-managed
npx hyperframes lambda deploy                                # once, your AWS account
npx hyperframes lambda render --wait                         # chunks render in parallel
  • HyperFrames Cloud: projects up to 200 MB are sent as one zip; larger media is uploaded separately, eight files at a time and cached for re-renders. Billed through HeyGen; the Free Studio plan includes 5 cloud exports a month.
  • AWS Lambda: a Step Functions workflow runs Plan, then many parallel chunk renders, then Assemble, with intermediate files in S3. Billed by AWS compute time.
  • Cloud Run: the same plan, parallel chunks, assemble shape, on Google Cloud.

Formats

Quality, size and frame rate

FlagEffect
--quality draftFaster review version
--quality looks (default)CRF 16, right for most finished work
--quality delivery / highLarger final master
--resolution 4k3840x2160. The docs say roughly 4x slower per frame and 3 to 5x larger files. I measured less
--fps 60More frames, so longer rendering. Default is the composition's data-fps or 30
--chroma-subsampling 444Sharper thin coloured text for masters; the docs say 2 to 3.5x slower. Not for files you publish, and not on Lambda or Cloud Run
--workers NParallel local Chrome workers
--gpu, --browser-gpuGPU encoding, or GPU for Chrome capture. Cloud paths are software-rendered for determinism
