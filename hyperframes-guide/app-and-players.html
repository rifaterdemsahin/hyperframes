🖥️ Desktop app or not? And how the player differs from Remotion's 🎞️

Two questions in one page: should you use the Hyperframes Studio desktop app for this video, and what is different about the player compared with Remotion's. Everything is from the official docs unless it says "my reasoning" or "what I saw".

📚 Sources checked 18 Nov 2026: the Hyperframes docs (Studio app, browser editor, @hyperframes/player, developer overview), made by HeyGen, who also make the app, so they are a vendor source; and Remotion's docs for the Player and Studio. 🧪 I did not use the app's chat or canvas myself, and I did not embed either player in a test page.

✅ My verdict for this project

Use the desktop app as a viewer and a finishing tool, not as the place where the video is written.

🧱 Why: this video is generated from script/scenes.json by scripts/build-video.mjs. When I opened the project in the app today it reformatted all 11 generated files (170 lines of whitespace changes), created a word-level transcript of the first voiceover and a thumbnail cache. Anything you change by hand in the app would be overwritten the next time the script is rebuilt.

🎯 So: yes to the app for watching the timeline, scrubbing, and placing your real footage once you have it (the ten placeholder frames). No to the app for wording, timing and layout: keep changing those in the script and the storyboard.

🔄 Once the real footage goes in, decide once: either keep generating from the script (and add footage through the script), or stop generating and treat video/ as hand-edited from then on. Doing both is what causes lost edits.

🖥️ The Studio desktop app in detail

👍 What it is good at

  • 🗣️ Say it or point at it. You describe a change, or point at or draw on the frame, and the agent edits the files.
  • 🔁 Picks up your Claude Code chat. npx hyperframes open run inside an agent session hands the project over and the app's chat carries on that conversation (Mac today). npx hyperframes catch-up then tells your agent what you did in the app.
  • 📂 Nothing is moved. Importing a project leaves it in its folder; changes are saved there.
  • 🎨 Extras: brand kits, reference-a-video-to-copy-its-style, AI voiceovers, captions, music and sound, and generated clips (HeyGen credits).
  • 💸 Free plan covers AI voiceovers, captions, music and effects, 3 AI clips and 5 cloud exports a month. Pro is $25/month and adds HeyGen's top models and unlimited cloud exports.

⚠️ What to watch for

  • ✍️ It rewrites files. It reformatted every generated file in this project the moment it opened it. Harmless to the render, but it makes git noisy and overwrites nothing until you rebuild, then your hand edits are lost.
  • 🔐 Sign-in with HeyGen is needed for the app (see Hyperframes sign-in).
  • 🪄 Auto-record manual edits as keyframes is on by default in the editor: a tweak at the playhead becomes animation. Switch it off for a fix that should hold for the whole scene.
  • 🍎 The hand-off that keeps your chat only works on Mac so far.
  • 🧩 Our video is generated, which is not the app's normal flow (it expects to author the project itself).

▶️ The player: Hyperframes vs Remotion

"Player" means the component you drop into a web page to play and seek a composition live, without rendering a video first. Both projects have one, and they are built very differently.

🟣 Hyperframes: <hyperframes-player>

  • 🧱 A web component (custom element). Works in plain HTML or any framework.
  • 📦 @hyperframes/player, or one script tag from a CDN.
  • 📄 Plays an HTML composition file by URL (src="./intro.html"), or an ordinary video file when you add type="video/mp4".
  • ⏱️ Time is in seconds: player.seek(2.5).

🔵 Remotion: <Player>

  • ⚛️ A React component. Needs a React app (Next.js, Vite and so on).
  • 📦 @remotion/player.
  • 🧩 Plays a React component you pass in directly (component or lazyComponent), with durationInFrames, fps, width and height. It does not use <Composition>.
  • 🎞️ Time is in frames: seekTo(frame).

🧪 What this means for this site

  • 📝 The Review page plays the exported MP4 in a plain <video>. That is deliberate: your feedback is tied to the exact file you will publish, to the frame, and drawings land on real pixels.
  • 🟣 A <hyperframes-player> would play the live composition with no render, seeking in seconds, and it reports the scene list. That would suit a "preview while editing" embed. I have not tested it here: it needs the video/ folder served and the CDN script, and frame-accurate drawing would be harder than on a video file.
  • 🔵 Remotion's Player would need this site to be a React app, so it is not a fit.
  • 🏁 Recommendation: keep the plain video for review, use the desktop app for footage and scrubbing, and consider the Hyperframes player only if you later want a live-preview embed.
