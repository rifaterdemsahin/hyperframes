Hyperframes vs Remotion

Both tools turn web pages into video: open a real browser, draw each frame, encode the result. The difference is what you write. Remotion asks for a React component. Hyperframes asks for an HTML file.

Source and bias: the comparison numbers and code below come from Hyperframes' own guide, written by HeyGen, who make Hyperframes. It is open about what Remotion does better, but treat it as a vendor source. The "for this project" section is my own reasoning.

Where they differ

HyperframesRemotion
You writeHTML, CSS and JavaScriptReact and TypeScript
How motion is timedMarkup declares when things are on screen (data-start, data-duration); a paused GSAP timeline declares how they move, in seconds. The renderer seeks it to each exact moment.A component reads the current frame number and returns the values for that frame. You do the timing math in frames.
Existing web materialHTML, CSS, GSAP or Lottie usually drop in close to as-isRewritten as React components
LicenceApache 2.0Its own licence: free for individuals and companies up to three people, paid above that (check current terms)
RenderingLocal (free, no account), HeyGen cloud, Google Cloud Run, AWS LambdaLocal and AWS Lambda; Lambda is mature and heavily documented
Visual editorStudio edits the same DOM the renderer capturesRemotion Studio edits React compositions
MaturityNewerOlder: more templates, tutorials, answers and production history

Same request, two agents (HeyGen's test)

Claude Code was given one prompt twice: a 15 second launch video, once with Remotion's agent skills and once with Hyperframes'. One run each, no retries. Both produced good videos; one run decides nothing about quality.

The same title card, written both ways

Remotion

import { AbsoluteFill, interpolate,
  useCurrentFrame } from "remotion";

export const TitleCard = () => {
  const frame = useCurrentFrame();
  // fade in 0-15, hold to 75, out by 90
  const opacity = interpolate(
    frame, [0, 15, 75, 90], [0, 1, 1, 0],
    { extrapolateLeft: "clamp",
      extrapolateRight: "clamp" });
  return (
    <AbsoluteFill style={{ background: "#0a0a0a",
      justifyContent: "center",
      alignItems: "center" }}>
      <div style={{ fontSize: 160, color: "#fff",
        opacity }}>HELLO</div>
    </AbsoluteFill>);
};

Hyperframes

</div>
<script>
  const tl = gsap.timeline({ paused: true });
  tl.to("#title", {opacity:1, duration:.5}, 0);
  tl.to("#title", {opacity:1, duration:2}, .5);
  tl.to("#title", {opacity:0, duration:.5}, 2.5);
  window.__timelines["title-card"] = tl;
</script>

Condensed from the official guide. Neither is obviously better: the Remotion one is a pure function you can reason about in your head; the Hyperframes one is a page you can open in a browser and inspect with devtools.

What Remotion does better

  • More established: more templates, tutorials, answered questions and production history.
  • Remotion Lambda is a mature rendering system; Hyperframes' cloud options are newer.
  • If your team already writes React, you reuse your components, design system and charting libraries, with typed, validated inputs.

For this video

Hyperframes is the better fit here, for these reasons:

  • Every number and date (£39,475.54, £1,500 + £2,100, 30 Oct, 19 Nov, 2 Dec) is plain HTML text you can edit and re-render, with no React build.
  • The storyboard, kanban and hub are already HTML, so the same overlays and CSS carry straight into the video.
  • The project is Apache 2.0 and installs nothing into the repo, which suits a public repo on GitHub Pages.
  • It is made for AI agents to write, which is how this video is being built, and the project's own docs steer me through it.

Remotion would make sense if you later wanted a React app that generates many videos from data, or already had React components to reuse.
