Hyperframes vs Remotion

Both tools turn web pages into video: open a real browser, draw each frame, encode the result. The difference is what you write. Remotion asks for a React component. Hyperframes asks for an HTML file.

Source and bias: the comparison numbers and code below come from Hyperframes' own guide, written by HeyGen, who make Hyperframes. It is open about what Remotion does better, but treat it as a vendor source. The "for this project" section is my own reasoning.

How to read it

  • Hyperframes grew much faster. About 10,000 stars a month against about 1,000 for Remotion over its lifetime, and it already has more stars. Stars measure attention, not quality, and a launch backed by a large company draws a lot of it.
  • Remotion is far more established. Roughly 3x the weekly downloads, 3x the contributors and 5.6x the commits, over a project about nine times as old. That matches the vendor guide's own admission that Remotion has more production history.
  • Hyperframes ships very fast. 651 releases in about 253 days is roughly 2.6 a day, against about 0.3 a day for Remotion. Good for fixes, but it also means frequent change, so this project pins hyperframes@0.9.67.
  • Version numbers. Hyperframes is at 0.9.x and Remotion at 4.x. By the usual semver convention a 0.x version can still change in breaking ways. Check release notes before upgrading.
  • Download counts are noisy. npm numbers include CI runs and AI agents running npx, and projects that pin npx --yes hyperframes@x (like this one) download on each run. Read them as a rough ratio, not a user count.
  • Both are active today: each repo had a push and a release on 18 Nov 2026.
  • Open issues include pull requests, so they are not a bug count.

The difference in practice: the tools cost the same for one person ($0). The gap appears when a team grows past three people or a company wants to automate rendering at volume: Remotion then charges a licence, Hyperframes does not. Cloud rendering costs are comparable, because both run on your own AWS account.

For this video: £0 licence cost either way, and rendering locally is free. So cost does not decide it, and the choice rests on the points in the section below.

The same title card, written both ways

Remotion

import { AbsoluteFill, interpolate,
  useCurrentFrame } from "remotion";

export const TitleCard = () => {
  const frame = useCurrentFrame();
  // fade in 0-15, hold to 75, out by 90
  const opacity = interpolate(
    frame, [0, 15, 75, 90], [0, 1, 1, 0],
    { extrapolateLeft: "clamp",
      extrapolateRight: "clamp" });
  return (
    <AbsoluteFill style={{ background: "#0a0a0a",
      justifyContent: "center",
      alignItems: "center" }}>
      <div style={{ fontSize: 160, color: "#fff",
        opacity }}>HELLO</div>
    </AbsoluteFill>);
};

What Remotion does better

  • More established: more templates, tutorials, answered questions and production history.
  • Remotion Lambda is a mature rendering system; Hyperframes' cloud options are newer.
  • If your team already writes React, you reuse your components, design system and charting libraries, with typed, validated inputs.

For this video

Hyperframes is the better fit here, for these reasons:

  • Every number and date (£1,500 + £2,100, 19 Nov, 2 Dec) is plain HTML text you can edit and re-render, with no React build.
  • The storyboard, kanban and hub are already HTML, so the same overlays and CSS carry straight into the video.
  • The project is Apache 2.0 and installs nothing into the repo, which suits a public repo on GitHub Pages.
  • It is made for AI agents to write, which is how this video is being built, and the project's own docs steer me through it.

Remotion would make sense if you later wanted a React app that generates many videos from data, or already had React components to reuse.
