📦 Video Releases & Storage Limits

Can you push video outputs to GitHub Releases? Yes, absolutely. Here is a breakdown of GitHub's official file limits, bandwidth quotas, architectural trade-offs, and step-by-step CLI commands for publishing master MP4 renders.

TL;DR Summary

GitHub Releases allows binary attachments up to 2 GB per file with no total limit on the sum of all releases. It is the official, CDN-backed location for compiled binaries and master video renders. In contrast, regular Git commits fail at 100 MB and bloat repository history.

1. Storage tier comparison for video projects

Video files are large binary blobs. How you store them determines whether your repository stays fast and maintainable or becomes unusable.

Storage Method Max Single File Total Quota Bandwidth Cost Git Clone Speed Verdict for Video Renders
GitHub Releases 2 GB per file Unlimited releases Free & CDN-cached No clone impact ⭐ Best for master MP4s, 4K cuts & archives
Git Repository (Tree) 100 MB hard limit Recommended < 1 GB Included with Git Bloats forever ❌ Never store full-res video in Git history

2. Why GitHub Releases is the right tool

🚀 Performance & Scalability

  • Global CDN Distribution: Release assets are automatically mirrored on Amazon S3 and Fastly CDN edges worldwide for maximum download speed.
  • Zero Repository Bloat: Release binaries live outside the Git commit tree. Cloning or pulling the repository remains lightning fast.
  • Generous 2 GB Headroom: Our 4-minute 1080p master render is 63 MB—which consumes only 3.1% of the single-file limit.

🔒 Stability & Link Predictability

  • Immutable Permalinks: Direct download URLs follow a deterministic pattern: https://github.com/<user>/<repo>/releases/download/<tag>/<file>.mp4
  • Zero Quota Surprises: Unlike Git LFS which suspends your repository if strangers download more than 1 GB in a month, public GitHub Releases do not charge bandwidth fees.
  • Release Notes & Provenance: Every video file is tied to an exact Git commit, tag, changelog, and draft version.

3. How to push video outputs to GitHub Releases

A. Using the Project Automation Script

This repository provides a dedicated script to package and publish the master 1080p render with one command:

node scripts/publish-release.mjs

To publish a specific draft or custom tag:

node scripts/publish-release.mjs --draft=7 --tag=v1.16.0

B. Using the GitHub CLI (`gh`) Directly

# 1. Create a release and attach the 1080p master render (63 MB)
gh release create v1.16.0 video/renders/first-draft.mp4#liquidation-draft-v7-1080p.mp4 \
  --title "Draft v7: Master 1080p Video" \
  --notes "Full-fidelity 1080p 30fps master render. Generated locally via Hyperframes."

# 2. Upload additional assets (thumbnails, captions) to an existing release
gh release upload v1.16.0 video/assets/bg/heros-journey.jpg#heros-journey-backdrop.jpg
