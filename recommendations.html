Why this page stopped updating

When: the last real change was on 18 Nov 2026 at 23:01 (site v1.8.0, Draft v2). After that came 9 more drafts (v3 to v11) and about 30 releases, and none of them changed a word here. It still said the film was 3:54, asked for the Skool link and the n8n logo, and flagged a costs line that had already been rewritten.

Why:

  • It is hand-written, and nothing makes it update. The draft, review, renders and changes pages are generated on every render. This page is not, so it only changes when someone remembers to edit it.
  • The feedback moved elsewhere. From Draft v3 on, your notes came through the Review page as feedback IDs, and they were tracked in the Kanban and the verification list. Releases were scoped to the pages each note touched, and this page was never one of them.
  • It looked fresh when it was not. Every release rewrites the ?v= cache-busters in every page, so this file appeared in almost every commit. Its own page version stayed at 1.7.0 (18 Nov), but the footer shows the site version, which hid that.
  • Its dependencies were wrong. They listed the script and the publish page, but not draft/versions.json, so a new draft never pointed back here.

Fixed now: this page records the draft it was reviewed against (data-reviewed-draft), and npm test fails when the latest draft is more than 2 drafts ahead. It now also depends on draft/versions.json. The same thing happened to other hand-written pages; see Stale pages.

URGENTRevoke the Azure storage tokens that are public

review.html holds container-level SAS URLs for two storage accounts, and they are published on the public repo and the live site. They allow read, add, create, write and list (plus delete on one), and they are valid until November 2027. The Fly server also hands the write token to anyone who calls /api/azure-config. Anyone can list, overwrite or (on one container) delete your review drawings and verification state, or store files in your account.

  • Revoke them: rotate the storage account keys that signed them, or, if they use a stored access policy, delete that policy. Removing them from the page is not enough, because they are in the git history from v1.21.0.
  • Then I change the design: the browser uploads through the Fly server (which holds the token), images are read through short-lived read-only links, and /api/azure-config stops returning the token.
